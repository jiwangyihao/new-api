# 领域文档

本文件规定工程技能在探索代码库时如何读取本仓库的领域文档。

## 布局

本仓库采用 **single-context** 布局：

```text
/
├── CONTEXT.md
└── docs/
    └── adr/
        ├── 0001-<decision>.md
        └── 0002-<decision>.md
```

`CONTEXT.md` 维护整个产品的领域语言；`docs/adr/` 保存影响整个仓库的架构决策。不要为 Go 后端、`web/default` 与 `web/classic` 建立相互独立的领域上下文，除非以后明确切换为 multi-context 布局。

## 探索前读取

1. 如果根目录存在 `CONTEXT.md`，先读取与当前任务相关的术语和边界。
2. 检查 `docs/adr/`，读取与即将修改区域相关的 ADR。
3. 文件或目录尚不存在时静默继续，不要仅因缺失而提前建议创建。`domain-modeling` 会在真正确定术语或架构决策时按需创建它们。

## 使用统一术语

Issue 标题、重构提案、诊断假设和测试名称中的领域概念，必须采用 `CONTEXT.md` 定义的词汇，不要漂移到其明确排除的同义词。

如果所需概念尚未出现在词汇表中，应先判断是否正在引入项目未使用的新语言；若确属领域模型缺口，则记录并交由 `domain-modeling` 处理。

## 标明 ADR 冲突

如果输出与现有 ADR 冲突，必须明确指出冲突，不得静默覆盖。例如：

> 与 ADR-0007 的既有决策冲突；建议重新讨论，因为……
